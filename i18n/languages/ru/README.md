## Функциональные характеристики

* Ввод`idleleo`Откройте меню управления Xray для управления установкой, службами, параметрами безопасности и т. д.
* Используется Qwen-MT-Plus AI для обеспечения точного многоязычного перевода.
* Поддерживает протокол Reality, рекомендуется использовать с предварительно установленным Nginx (может быть установлен в скрипте)
* Поддерживает передачу по протоколам WebSocket, gRPC и xHTTP; можно выбрать один из режимов передачи или`ws+gRPC+xHTTP`Одновременно включить
* Поддержка двойного стека IPv4 / IPv6: при установке автоматически проверяется возможность выхода в Публичную сеть, по доменному имени A/AAAA выполняется независимая проверка и генерируются соответствующие ссылки для совместного доступа и конфигурация Clash.
* Встроенная защита fail2ban (может быть установлена внутри скрипта)
* Встроенные функции: статистика трафика Xray, блокировка трафика, обновление правил GeoIP/GeoSite и обновление по расписанию.
* Поддерживает обновления скриптов, Xray, Nginx и сертификатов, а также предоставляет резервное копирование и откат в случае сбоя для важнейших обновлений.
* Перед переустановкой и переключением режима автоматически создается резервная копия текущей рабочей конфигурации; в случае сбоя восстанавливается исходная конфигурация.
* Переконфигурация предоставляет три безопасных пути: повторное развертывание сохранённой конфигурации, восстановление на основе стандартного шаблона и переключение режима.
* Принимает[@DuckSoft](https://github.com/DuckSoft)Ссылка для обмена[Предложение](https://github.com/XTLS/Xray-core/issues/91)(beta), совместимо с Qv2ray, V2rayN, V2rayNG
* Принимает[XTLS](https://github.com/XTLS/Xray-core/issues/158)Предложение, следуя[UUIDv5](https://tools.ietf.org/html/rfc4122#section-4.3)Стандарт, поддерживающий пользовательское сопоставление строк с VLESS и UUID.
* Поддержка протокола gRPC:[Использовать протокол gRPC](https://hey.run/posts/xrayjin-jie-wan-fa---shi-yong-grpcxie-yi)
* Поддержка балансировки нагрузки Reality / ws/gRPC/xHTTP:
  - [Развернуть балансировщик нагрузки Reality в REALITY](https://hey.run/posts/bushu-reality-balance)
  - [Настройка балансировки нагрузки на стороне сервера](https://hey.run/posts/xrayjin-jie-wan-fa---da-jian-hou-duan-fu-wu-qi-fu-zai-jun-heng)
* Reality + Nginx режим включён по умолчанию SNI Guard: неизвестные SNI, пустые SNI и аномальные TLS не попадают в Xray Reality бэкенд; по умолчанию применяется стратегия изоляции (ssl_reject_handshake), продвинутые пользователи могут переключиться на резервное использование собственного decoy сайта или сразу TCP отклонять запросы. Эта функция предназначена для снижения активного сканирования и уменьшения уязвимостей, вызванных неправильной конфигурацией, и не ставит целью идеальную маскировку.

## Подготовительная работа

* Один зарубежный сервер, имеющий публичный IP
* Установка протокола Reality: необходимо подготовить целевой домен, соответствующий требованиям Xray.
* Установка версии TLS: необходимо подготовить доменное имя и правильно настроить записи A и/или A в соответствии с доступной сетью сервера; в среде двойного стека рекомендуется одновременно настроить корректные записи A и A. Скрипт поддерживает автоматическое определение сетевой возможности IPv4/IPv6; при наличии двойного стека он может одновременно сформировать соответствующие точки входа для клиентов.
* Чтение[Xray Официальная документация](https://xtls.github.io), ознакомьтесь с концепциями Reality, TLS, WebSocket, gRPC и Xray в контексте REALITY
* **Убедитесь, что установлен curl**: пользователь CentOS выполняет`yum install -y curl`Пользователь выполняет Debian/Ubuntu`apt install -y curl`

## Режим установки

| Режим | Описание |
|------|------|
| Reality + Nginx | Рекомендуемый режим, при необходимости можно добавить простой протокол ws/gRPC/xHTTP для балансировки нагрузки. |
| Nginx + TLS | Поддерживает ws/gRPC/xHTTP и автоматически оформляет и продлевает сертификаты Let's Encrypt. |
| ws/gRPC/xHTTP ONLY | Режим независимого входящего соединения без TLS, в основном используется для бэкенд-систем или сценариев балансировки нагрузки. |
| Узел пересадки | Роль отдельного сервера, использующего только Nginx и Stream для перенаправления на один целевой объект TCP, без установки Xray. |
| Docker | В образе предустановлены Xray, Nginx и основной скрипт. |

При установке соответствующего режима ws/gRPC/xHTTP, можно выбрать`ws`, `gRPC`, `xHTTP`Или`ws+gRPC+xHTTP`Скрипт сгенерирует соответствующие порт, путь, ссылку для обмена и QR‑код; в настоящее время Clash не поддерживает xHTTP, о чём скрипт уведомит в выводе конфигурации.

## Инструкция по перенастройке

При повторном запуске установки в уже установленной среде скрипт автоматически создаст резервную копию текущей конфигурации и предложит три варианта перенастройки:

| Путь | Описание | Ограничение |
|------|------|------|
| Сохранить конфигурацию и повторно развернуть | Сохраняются пользовательские настройки routing/outbounds/DNS и многопользовательская конфигурация, изменяются только поля, выбранные пользователем (порт, путь, параметры UUID, Reality и т. д.) | Не поддерживается перенос изменений структуры (например, ws → gRPC); для изменения набора передаваемых объектов необходимо воссоздать его с использованием стандартного шаблона. |
| Стандартная шаблонная реконструкция | Создайте стандартную конфигурацию шаблона, используя текущие повторно используемые параметры; пользовательский routing/outbounds/DNS может быть удалён. | Не требуется обязательное сохранение числа пользователей. |
| Переключение режима | Переключение на другой протокольный режим (например, Reality → TLS), по умолчанию повторно используется только основной пользователь UUID/email | Другие пользователи не будут перенесены автоматически; перед переключением будет выведено соответствующее уведомление. |

При сбое на любом этапе перенастройки (запись конфигурации, запуск сервиса, проверка работоспособности и т. д.) происходит автоматический откат к резервной исходной конфигурации. Директория резервных копий использует уникальный временной метку, что позволяет выполнять последовательные многократные перенастройки без конфликтов.

## RillML Xray AI-ассистент по эксплуатации и обслуживанию

RillML (сокращённо Rill) предоставляет Xray возможности локальной адаптивной интеллектуальной эксплуатации и обслуживания.

Встроен помощник по эксплуатации и обслуживанию на базе локального AI, который в режиме реального времени отслеживает состояние здоровья Xray/Nginx, автоматически диагностирует неисправности и предлагает рекомендации по их устранению, без необходимости в стороннем API. В главном меню введите`9`Или выполнить`idleleo --rill-agent`Войти.

**Ключевые компетенции**

* Мониторинг: в режиме реального времени отслеживаются состояние службы Xray/Nginx и конфигурации.
* Диагностика: определение первопричины неисправности с указанием уровня достоверности (высокий / средний / низкий / недостаточно доказательств)
* Определение: автоматическое определение типа неисправности и предоставление рекомендаций по её устранению; в пояснении чётко указывается, допускается ли автоматическое устранение или предоставляются только рекомендации.
* Режим: интеллектуальное определение / только наблюдение / безопасное отключение; до активации автоматического изменения система не будет изменена.

**Часто используемые команды**

| Операция | Команда |
|------|------|
| Открыть меню помощника по эксплуатации AI | `idleleo --rill-agent` |
| Установить или восстановить движок AI-оценки | `idleleo --rill-agent-install` |
| Просмотреть состояние оценки AI | `idleleo --rill-agent-status` |
| Запуск диагностики неисправностей с помощью AI | `idleleo --rill-agent-diagnose` |
| Проверка движка принятия решений на основе AI | `idleleo --rill-agent-verify` |
| Безопасное отключение AI-оценки | `idleleo --rill-agent-safe-disable` |
| Удалить Rill AI-движок | `idleleo --rill-agent-uninstall` |

Двигатель принятия решений на основе AI в настоящее время всё ещё находится в стадии тестирования; рекомендуется ориентироваться преимущественно на диагностические рекомендации, по умолчанию система не будет изменяться автоматически.

## AI Skill развертывание

Поддерживается автоматическое развертывание Xray с помощью AI-инструментов (например, Trae), без необходимости ручного взаимодействия. Подробности см.[Xray_bash_onekey_skill](https://github.com/hello-yunshu/Xray_bash_onekey_skill).

Традиционный способ требует SSH на сервер, запуск скрипта установки и поочередный ответ на интерактивные вопросы; в случае Skill достаточно сообщить AI о своих требованиях, AI автоматически сгенерирует неинтерактивный скрипт и выполнит его, сразу предоставив ссылку на VLESS.

**Режим поддержки**: Reality / TLS / ws ONLY / узел пересадки

**Способ использования**: в AI-инструменте, поддерживающем Skill, просто скажите «Помоги мне развернуть Xray на сервере», и AI автоматически соберёт информацию, сгенерирует скрипт, выполнит развертывание и вернёт данные для подключения.

## Важные замечания

* Если вы не понимаете назначение настроек, кроме обязательных полей используйте значения по умолчанию (достаточно нажимать Enter на протяжении всего процесса).
* Пользователи Cloudflare, пожалуйста, активируйте CDN только после завершения установки.
* Данный скрипт требует базовых знаний о Linux и общих сведений по компьютерным сетям.
* Поддерживается Debian 12+ / Ubuntu 24.04+ / CentOS Stream 10+, у некоторых шаблонов CentOS могут возникать проблемы при компиляции; в случае возникновения проблем рекомендуется сменить систему.
* Рекомендуется развертывать на одном сервере только один агент, используя порт 443 по умолчанию.
* Преобразование пользовательской строки в UUIDv5 требует поддержки со стороны клиента.
* Рекомендуется использовать в чистой среде; новичкам не следует использовать CentOS
* Данная программа зависит от Nginx, уже проверено.[LNMP](https://lnmp.org)Пользователям, у которых скрипт уже установил Nginx, следует обратить внимание на возможные конфликты.
* Ссылка для общего доступа xHTTP применима к клиентам, поддерживающим xHTTP; вывод конфигурации Clash пропускает xHTTP.
* Не используйте данный скрипт в продакшен-среде до проверки его работоспособности.
* Автор: Юнь Шу, предоставляется лишь ограниченная поддержка.

## Настройка сертификатов

**Пользовательский сертификат**: переименуйте файлы crt и key соответственно в`xray.crt`И </tool_response>`xray.key`, поместить в`/etc/idleleo/cert`Каталог (если каталога нет, создайте его). Обратите внимание на права доступа и срок действия сертификата; после истечения срока действия пользовательского сертификата необходимо самостоятельно продлить его.

**Автоматический сертификат**: скрипт поддерживает автоматическое создание сертификата Let's Encrypt (срок действия — 3 месяца) и, в теории, автоматическое продление.

## Просмотреть конфигурацию клиента

```bash
cat /etc/idleleo/info/xray_info.inf
```

## Xray Введение

* Xray — это отличный открытый инструмент для работы с сетевыми прокси, поддерживающий все платформы, включая Windows, macOS, Android, iOS и Linux.
* Этот скрипт является скриптом для полной настройки одним нажатием; после успешного завершения всех этапов можно настроить клиент в соответствии с выведенными результатами и приступить к использованию.
* **Настоятельно рекомендуется** полностью разобраться в порядке работы и принципах функционирования программы.

## Управление услугами

| Операция | Команда |
|------|------|
| Запустить Xray | `systemctl start xray` |
| Остановить Xray | `systemctl stop xray` |
| Запустить Nginx | `systemctl start nginx` |
| Остановить Nginx | `systemctl stop nginx` |

## Соответствующий каталог

| Содержание | Путь |
|------|------|
| Главная директория | `/etc/idleleo` |
| Конфигурация Xray | `/etc/idleleo/conf/xray/config.json` |
| Конфигурация Nginx | `/etc/idleleo/conf/nginx/` |
| Информация об установке | `/etc/idleleo/conf/install_config.json` |
| Файл сертификата | `/etc/idleleo/cert/xray.key`, `/etc/idleleo/cert/xray.crt` |
| Каталог журналов | `/etc/idleleo/logs/`, `/var/log/xray/` |
| Директория установки Nginx | `/usr/local/nginx` |
| Команда управления | `/usr/bin/idleleo` |
