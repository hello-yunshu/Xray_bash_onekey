## 1. S4 判据

| # | 判据（记忆中的方案结论） | 验证方式 |
|---|---|---|
| S4.1 | ACME 采用 **lego 库模式**，不引入 `lego` 外部二进制、不调用 `acme.sh` | `go.mod` 依赖 + 源码 import；仓库内无新增二进制 |
| S4.2 | 依赖以 **vendor** 形式落地，离线（`GOPROXY=off`）可构建 | 容器内 `GOPROXY=off go build ./...`、`go test ./...` |

**执行时确定**：lego 版本取 `v5.6.0`（当前最新，`go 1.26.0` 要求低于本仓库
`go 1.27.4`）；`go mod vendor` 只落本模块实际 import 的包，不手工裁剪。

## 2. S5 判据

| # | 判据（记忆中的方案结论） | 验证方式 |
|---|---|---|
| S5.1 | ACME 协议层（账户、订单、HTTP-01、CSR、finalize、下载）由 lego 承担 | `internal/acme` 不再实现 JWS/nonce/订单状态机 |
| S5.2 | **必须留在 Go 侧**：证书对原子替换、权限（证书 0644 / 私钥 0600）、`nginx -t` 校验、服务 reload、失败回滚 | 保留 `replacePair`/`restorePair`/`runReload` 与单元测试 |
| S5.3 | 现有 `idleleo xray cert issue\|renew` 行为不回退：目录 URL 必须显式、窗口外跳过、`--force` 重签、`--json` 输出 | 单元测试 + Pebble 容器验收 |
| S5.4 | HTTP-01 token 先按 base64url 校验再写 webroot | `validToken` 测试 + 阴性用例 |
| S5.5 | 验收仍是 `ACME_LOCAL_CA`，不得据此把 F12 升格 | Pebble 容器 `run_acme_container.sh` |
| S5.6 | 替换原 shell 路径：Go 内不再依赖 `acme.sh`/`ssl_update.sh` 完成签发 | 源码检索 + 容器验收 |

**执行时确定**：`Renew` 仍采用“读当前证书 NotAfter → 窗口判断 → 重新 Obtain”的
既有语义（不改成 lego 的 `Renew`，因为它要求把旧 resource 完整持久化，会引入新的
状态文件契约）；每次签发使用新私钥，与现有行为一致。

## 3. 冲突与决定（按用户要求先记录再执行）

### C1：lego 库模式曾被判定“不可行”

- 早期审计结论：lego v5.6.0 要求 Go 1.26.0，而当时项目固定在 Go 1.23/1.24，
  因此只能采用**固定版本外部二进制**。
- 现状：项目已升级到 `go 1.27.4`，该前提消失；后续评估已改为“库模式 + vendor”，
  体积约 +13MB，优于外部二进制单架构 41.6MB。
- **决定**：按 S4 指令执行库模式；早期“外部二进制”结论作废，不引入外部二进制。
  记录为 D-020。

### C2：D-015 的 stdlib 实现被取代

- D-015 记录 `internal/acme` 用 stdlib 实现 ACME v2。
- S5 要求协议层改用 lego。D-015 中**仍然有效**的部分是：目录 URL 必须显式传入、
  Pebble 本地 CA 验收、证据标签 `ACME_LOCAL_CA`、不得升格为 `REAL_VPS_VERIFIED`。
- **决定**：D-015 标记为“协议实现由 D-020 取代，验收与标签约束继续有效”。

### C3：F12 签收状态不能随 S5 变化

- `F12` 的名称是“证书签发续期清理”，已文档化的签收门槛是**真实公网域名 + 公网 CA
  + DNS-01/EAB**；本地 Pebble 只能证明协议与事务，不能签收 F12
  （`BASH_GO_REAL_RUNTIME_PARITY_REPORT.md`、`FEATURE_PARITY_RESULTS.md` 均已写明）。
- 另外 `check_preview_gate.py` 的 S3 不变量要求 `feature_contracts.json` **保持
  28 项全部 PENDING**；单方面把 F12 改为 `VERIFIED_GO_PARITY` 会让 preview 门禁
  直接拒绝运行。
- **决定**：S5 完成后 F12 **保持 `PENDING_GO_IMPLEMENTATION`**，不动
  `feature_contracts.json`。理由：签收所需的公网 CA/DNS-01/EAB 环境本轮不具备，
  且账本变更会破坏 S3 的 preview 只读不变量。S5 的完成判据是“协议层替换 +
  本地 CA 全流程 + 事务/负面用例”，不是 F12 签收。

### C4：S7 边界

- `tcp.sh`、`superspeed.sh`、`acme.sh`、helper 下载、版本 JSON、
  `assets/go/manifest.json` 属于 S7，本轮不碰；`check_release_gate.py` 一个字节不动。
- 因此“替换 shell 路径”只指 **Go 运行路径不再依赖 shell 完成签发**，不删除仓库里
  的 `acme.sh` 入口（那是 S7 的删除/接管工作）。

## 4. 明确不做

- 不引入 lego 外部二进制，不调用 `acme.sh`。
- 不做 DNS-01/EAB/公网 CA 验收，不据此改 F12 状态。
- 不改 `check_release_gate.py`，不改 28 项账本。
- 不实现 S6/S7 的插件化、TCP/测速、版本 JSON 与 `assets/go/manifest.json`。
