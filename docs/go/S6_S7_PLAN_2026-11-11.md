## 5. 顺序、增量与风险

### 5.1 建议顺序

```
S6-0 ──> S6-3 ──> S6-2
   │        │
   ├──────> S6-1 ──> S7-2
   │
   └──────> S7-1 ──> S7-3
                     
S7-4（原子，S6-0 后随时可做，建议放在 S7 末尾前）
S7-5（最后）
```

理由：

- **S6 先**：S7 的 `tcp.sh` 退役依赖 S6-1 的接线；`superspeed.sh` 退役依赖 S7-1；
  先下线会让用户失去入口。
- **S6-3 早做**：它是信任根，且 memory 已判定“无需等待 Go 重构即可落地”。
- **S7-4 原子提交**：签发、续签 cron、卸载、备份白名单必须一起改，
  单独删入口会造成现网续签中断。
- **S7-5 最后**：必须等所有交付面稳定后由流水线产出。

### 5.2 可独立发布的增量

| 增量 | 可独立发布 | 说明 |
|---|---|---|
| S6-0 | 是 | 纯卫生，无行为变化 |
| S6-1 | 是 | 只改 TCP 入口，可单独回滚 |
| S6-2 | 是 | 只收紧下载校验；失败可退回版本门控 |
| S6-3 | 是 | 纯加固；保留双读兼容期 |
| S6-4 | 视范围 | 若纳入，建议单独立项，不与 S6-1/2/3 绑死 |
| S7-1 | 是 | 新命令，不影响现有菜单 |
| S7-2 | 是（依赖 S6-1） | 只改 `install.sh` TCP 分支 |
| S7-3 | 是（依赖 S7-1） | 只改菜单 33 |
| S7-4 | **否** | 必须与续签 cron、卸载、备份一起原子提交 |
| S7-5 | 是（最后） | 会改变候选发布物，需显式批准 |

### 5.3 会破坏门禁的动作

| 动作 | 影响 | 结论 |
|---|---|---|
| 修改 `feature_contracts.json` 任一状态 | `check_preview_gate.py` 立即失败（要求 28 项全 PENDING） | **S6/S7 期间禁止** |
| 新增/删除/重命名 F 编号 | preview 与 release 都会失败 | **禁止** |
| 修改 `check_release_gate.py` | 违反硬约束 | **禁止** |
| 新增 `features/Fxx_test.py` | 不破坏 preview；单独存在也不会让 release 变绿 | 允许，但与账本变更分开评审 |
| 刷新 `assets/go/manifest.json` | 不破坏门禁；会改变自更新候选物 | 需要显式批准 |
| 删除 `install.sh` 的 `acme.sh`/`tcp.sh`/`superspeed.sh` 分支 | 不影响门禁；影响现网 | 需要迁移与回滚路径 |

### 5.4 已消解的待定项

| 原待定项 | 结论 | 依据 |
|---|---|---|
| 测速保留还是下线 | **保留**：S7 新增 `idleleo speedtest` | S7 主题条目明确写 `idleleo speedtest`；`superspeed.sh` 下线后必须有替代 |
| S7-1（版本 JSON 签名）是否提前 | **已消解**：它现在就是 S6-3，S6 本就先做，不再存在“提前”问题 | 按主题归类后重新编号 |
| S6-4 插件化是否属于 S6 | **未消解**，仍待拍板 | 主题“安全与流量”不能自然覆盖“插件分发形态”；见下 |

### 5.5 仍需用户拍板的条目

1. **S6-4 插件化是否纳入本轮 S6**。建议：不纳入，单独立项。
   理由：它与“安全与流量”的关联只在完整性校验，主体是交付形态；
   且原始批次归属缺失，强行归入会扩大本轮范围。
2. **manifest 是否也纳入 Ed25519 签名范围**。建议：纳入，但放在 S7-5；
   理由：S6-3 只签版本 JSON，若 manifest 不同步签名，自更新通道仍是较弱环节。
3. **`acme.sh` 退役时对 `/root/.acme.sh` 的清理力度**：仅停止使用并保留目录，
   还是迁移后删除。建议：先“停止使用 + 保留目录一个版本”，再删除；
   理由：账户与证书回滚需要原目录。

### 5.6 风险表

| 风险 | 触发点 | 缓解 | 回滚 |
|---|---|---|---|
| 现网证书续签中断 | S7-4 删除 `acme.sh` cron/路径 | legacy 开关保留一个版本；先双跑；记录组权限差异 | 恢复 `ssl_update.sh` cron 与 `acme.sh` 入口 |
| 加固内核用户失去入口 | S7-2 默认不再下载 `tcp.sh` | S6-1 先接线；legacy 显式确认 | 恢复菜单 28 旧分支 |
| 菜单 33 失效 | S7-3 在 S7-1 未完成时下线 | 强依赖 S7-1 | 恢复旧下载分支 |
| 版本 JSON 签名不同步导致安装全失败 | S6-3 单边强制签名 | 双读兼容期 + 内置回退 + 告警 | 关闭强校验开关 |
| helper 校验收紧导致旧版本安装失败 | S6-2 统一 sha | 版本未变不覆盖；缺失时告警一个版本 | 回退到版本门控 |
| manifest 与产物不一致 | S7-5 手改 | 只由 `publish-go-bridge.yml` 产出 | 回退 manifest |
| vendor 重复文件引发卫生歧义 | S6-0 未清理 | 先清理再开发 | 无（纯删除） |
