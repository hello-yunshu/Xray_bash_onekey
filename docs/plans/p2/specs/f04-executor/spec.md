## 1. 目标

为 `feature_contracts.json` 的 F04（`Reality主次级负载均衡`，P1）建立真实夹具
`tests/go-parity/parity/features/F04_test.py`，覆盖：

   角色必需、Xray 入站端口、Nginx 前置端口、监听地址、Reality 参数、分享链接与 Clash；

   `03-isolate.conf`、SNI deny 端口、`--backend` 多后端；
3. SNI Guard 策略：默认/`isolate`、`reject`，以及 Go 明确拒绝的 `decoy`；
4. 参数与安全边界：角色、serverName 数量、保留端口、非 raw 传输、非法/冲突后端；
5. 真实校验：每份有效配置跑真实 `xray -test`；primary 的 stream 配置在
   `load_module` 后跑真实 `nginx -t`；

   `nginx_reality_servers_add`、`nginx_reality_serverNames_add`、`write_isolate_site_config`、
   `nginx_reality_conf_add`（含 `modify_nginx_port`），差异逐条写入 `baseline-compare.json`；
7. 明确登记本轮无法覆盖或不应伪造的缺口（双机数据面、真实服务启动、防火墙等）。

## 3. 设计决定

- **执行器是证据补齐，不是重写。** 只新增夹具、证据与文档计数；生产代码只改事实 16 暴露的
  保留 publicPort 缺口（最小修复 + 单测），其余差异登记不粉饰。
- 所有断言基于实际产物：tag、片段名、deny 端口、分享字段从 payload/文件读取后断言不变量；
  实测值写入 `observed.json`，不写死未核实数值（本规格 §2 的数值全部来自本轮实测）。
- 拒绝场景统一断言：`rc == 2`、`--out` 不存在、`--nginx-out` 不存在、`--fragments-out` 不存在。
- primary 必须同时跑真实 `xray -test` 与真实 `nginx -t`；secondary 必须断言零 Nginx 产物。
  `nginx -t` 的 harness 适配（`load_module`、把 `/etc/idleleo/conf/nginx` 与
  `/usr/local/nginx/logs` 改写到临时目录）写入 `observed.json` 与 `baseline-compare.json`，
  不宣称验证了真实安装路径。
- Bash 基线真实执行（从固定 `install.sh` 按函数边界提取，在临时目录执行）：
  `apply_install_profile`、`modify_inbound_port`、`modify_reality_listen_address`（仅静态断言未调用）、
  `nginx_reality_servers_add`、`_cleanup_stale_serverNames_fragments`、
  `_validate_serverNames_fragment`、`nginx_reality_serverNames_add`、
  `write_isolate_site_config`、`add_sni_guard_http_include`、`nginx_reality_conf_add`、
  `modify_nginx_port`，配 `judge`/`log_echo`/`gettext` 空实现与
  `sni_guard_port_conflicts(){ return 1; }`；TTY/网络函数
  （`menu_install_reality_balance_role`、`reality_balance_add_fq`、`sni_guard_policy_choose`、
  `install_xray_reality`）只做静态断言并标 `mode: static`。
- 固定测试输入：`example.com`、`--port 8443`、`--uuid eeeeeeee-…`、`--short-id abcd1234`、
  后端 `10.0.0.2:9443` 与 `backend.example.net:9443`；不写真实凭据，不联网。

## 4. 精确测试计划

文件：`tests/go-parity/parity/features/F04_test.py`（新建，复用 `run_fixture`）。

### S1 primary 默认
- 命令：`xray generate --mode reality-balance --role primary --server-names example.com
  --port 8443 --uuid <fixed> --short-id abcd1234 --out … --nginx-out … --fragments-out … --json`。
- 断言：`rc=0`；payload `mode/transport/port=9443/publicPort=8443/listen/balanceRole=primary/warnings=[]`；
  运行配置 0600、单入站、Reality 字段、routing、UUID/flow；
  分享 URI 与 Clash 的关键字段（scheme/host/port/security/sni/flow/sid/pbk/type、Clash reality-opts）；
  Nginx 配置包含 stream 骨架、两个 include、`deny 9403`、`listen 8443`、`ssl_preread on`；
  片段恰好 3 个且内容逐字节符合 §2；
  真实 `xray -test`、真实 `nginx -t` 均 `rc=0`。

### S2 secondary
- 断言：`rc=0`；入站 `port=8443`、`listen=0.0.0.0`、Reality 字段同 S1；
  `--nginx-out` 不存在、`--fragments-out` 不存在；分享端口 8443；`xray -test` `rc=0`。
- `--role secondary --backend 10.0.0.2:9443` → `rc=2`，消息含 `--backend is primary only`，零写盘。

### S3 SNI 策略
- 默认 = isolate：`deny 9403` + `03-isolate.conf`（断言全文）。
- `reject`：`deny 9404`、片段恰好 2 个、无 `03-isolate.conf`；`nginx -t` 通过。
- `decoy`：`rc=2`、零写盘、消息含 `decoy`。
- 未知策略（`bogus`）：`rc=2`、零写盘。

### S4 多后端
- `--backend 10.0.0.2:9443 --backend backend.example.net:9443`：两个新片段 + 本机片段，
  行逐字节匹配；运行配置与 payload 不变。
- 相同 `host:port` 重复一次：`rc=0` 且只生成一个片段。
- `--backend 127.0.0.1:9443`：与默认本机行去重，不产生额外文件。
- 同 host 不同端口、缺端口 `10.0.0.2`、host 含 `/` 或 `..`、端口 0/70000：`rc=2` 零写盘。
- IPv6 `[2001:db8::2]:9443`：片段名 `2001:db8::2.realityServers`，行为
  `server [2001:db8::2]:9443 …`；`nginx -t` 通过。

### S5 角色、默认值与端口守卫
- 缺 `--role`、`--role bogus`：`rc=2`，消息含 `requires --role`，零写盘。
- 默认端口：primary → `port=9443/publicPort=443`；secondary → `port=443`。
- `--port` 为 9403/9404/9443/9444：逐个 `rc=2`，零写盘。
- 修复后 `--port 8443 --public-port 9443`（primary）与 reality-nginx 同形态：`rc=2`
  消息含 `public port` 与保留端口集合；secondary 的 `--public-port` 仍只影响客户端视图。
- `--transport ws` / `grpc` / `xhttp` / 组合：`rc=2` 零写盘。
- `--server-names a.com,b.com`：`rc=2` 零写盘。

### S6 Bash 基线（真实执行）
- 静态：角色 profile 映射、模板 9443/0.0.0.0、保留端口集合、
  `modify_reality_listen_address` 仅在 `add_balance=off` 调用、菜单文案与角色选择。
- 真实执行：
  1. `apply_install_profile` 两角色 → 变量与 `shell_mode` 断言；
  2. 模板副本 + `modify_inbound_port`（primary `add_nginx=on`、secondary `add_nginx=off`）
     → primary 9443、secondary 8443；两份再跑真实 `xray -test`；
  3. `nginx_reality_servers_add` → 本机行逐字节；
  4. 预置损坏的 `stale.example.serverNames` → `nginx_reality_serverNames_add` 删除旧片段并写新行；
  5. `write_isolate_site_config` + `add_sni_guard_http_include` → 文件内容与 http include 断言；
  6. `nginx_reality_conf_add`（port=8443，isolate 与 reject 各一次，stub `judge`/`log_echo`/`gettext`、
     `sni_guard_port_conflicts` 返回 1、`save_originconf=Yes`）→ 产出的 stream 配置与 Go
     `nginx.conf` 逐字节对比（路径使用 Bash 默认值），并各自跑真实 `nginx -t`。
- `bash-result.json` 记录每个函数的命令、rc、产物路径与关键 stdout；`baseline-compare.json`
  覆盖 §3.1 全部条目。

### S7 真实校验汇总
