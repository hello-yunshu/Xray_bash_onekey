# Xray_bash_onekey 如何启动修改

## 所有项目的启动方式

远程审计文档分支统一为 `audit/2026-10-05`。先 fetch 并切到该分支，再创建独立修复分支；保持用户已有改动，分支切换失败先查看 git status，不能 reset/clean。

```sh
git fetch origin
git switch audit/2026-10-05
```

只看本目录的新合并文件。一次给模型一个任务，任务内它要自主依次完成所有 ID，不需要用户为每个 ID 重新发起。完成后审阅修复记录与测试，再启动下一份。真实 Linux/OpenWrt 资格仍是独立执行环境要求，不是“合并阶段后取消的测试”。

## 先在源头仓库启动

阶段 1/2 请在 `rill-xray-agent` 项目使用它的同名提示词。共享的 XRA 问题修一次即可，不要让 Xray 和 canonical 模型同时改生成镜像。

源头两个任务完成并提交后，回到 Xray 创建 `fix/audit-xray-host-integration`，用下面这段启动主仓任务：

```
请读取 AUDIT_2026-10-05/00-审计报告与执行顺序.md，完整执行
AUDIT_2026-10-05/03-主仓同步与发布准入.md。
先确认兄弟 rill-xray-agent 的两个合并任务已完成并取得准确修复提交，
按现有工具同步 canonical pin/digest、payload 和 bundle；然后修 GeoData 与发布 gate。
保留审计证据和用户改动，逐项写回归并运行 host/跨仓资格。
这次要实际改代码，不只给方案。未执行的 Linux/PID1 测试明确标记。
在独立修复分支本地提交，给出 ID 对照和测试结果；不自动合并 main 或发版。
```

## 跨项目顺序

1. **RillML** 一次任务先完成 Runtime 资源/状态/时间与工具链修复；它不阻塞 Cloudflare 本身的配置纯验证/锁/复用修复，也不阻塞 canonical 的 HTTP/备份修复。
2. **Cloudflare** 跑本仓两个任务；之后用包仓的资格更新提示消费已验证的 RillML 修复提交，再完成真正 OpenWrt 集成资格。
3. **Rill Xray Agent** 两个源头任务验收并提交，记录 exact commit/digest。
4. **Xray** 跑合并阶段 3：消费源头修复，完成 GeoData 和发布 gate，再做完整 Linux host 资格。
5. **rill-openwrt-packages** 按其 00-依赖审计与修复后资格更新提示词更新包 pin/资格，再回到 Cloudflare 更新依赖合同。Native stable 与 CF Preview 使用不同协议/发布资格，不能把相同 pin 强推给两边。

这不是要求把所有项目挤进一个上下文。不同项目可独立启动，但下游同步必须等待上游验收；同一个状态/镜像不要由两个任务同时写。
