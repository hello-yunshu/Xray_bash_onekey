## Назначение

Этот проект — скрипт развёртывания и эксплуатации Xray, написанный на Bash. Он объединяет установку, сертификаты, фронтенд Nginx, клиентскую конфигурацию, управление службами, резервное копирование и восстановление, а также повседневную диагностику в одном меню. Он подходит пользователям, которые хотят быстро поднять прокси на одном сервере без ручного сопровождения всей конфигурации.

Скрипт формирует конфигурацию и управляет службами, а Xray выполняет само проксирование. Режимы Reality и TLS лучше работают с фронтендом Nginx. Перед каждой критической записью выполняется проверка синтаксиса или резервное копирование, а при сбое выполняется откат, чтобы работающая служба не осталась в незавершённом состоянии.

| Управление безопасностью | fail2ban, блокировка трафика, SNI Guard, межсетевой экран и сертификаты |
| Повседневная эксплуатация | Управление службами, изменение конфигурации, очистка журналов, просмотр трафика по портам, резервное копирование и восстановление |

## Поддерживаемые системы

| Система | Версия | Примечания |
|---|---|---|
| Debian | 12, 13 | Использует `apt`; CI проверяет `debian:12-slim` и `debian:13-slim` |
| Ubuntu | 24.04, 26.04 | Использует `apt`; CI проверяет `ubuntu:24.04` и `ubuntu:26.04` |
| CentOS Stream | 10 | Использует менеджер пакетов RPM; CI проверяет `quay.io/centos/centos:stream10` |
| Rocky / AlmaLinux | 10+ | Рассматриваются как семейство RPM; основная версия должна быть не ниже 10 |

Скрипту требуются root, systemd, публичный IP-адрес и рабочий исходящий доступ к сети. При установке автоматически добавляются зависимости `curl`, `jq`, `openssl`, `qrencode` и `nmap`. Для режимов Reality/TLS также нужен домен с корректными записями A и/или AAAA для сети сервера.

> Неподдерживаемые системы отклоняются до установки. Шаблоны CentOS сильно различаются; при проблемах со сборкой или зависимостями используйте Debian или Ubuntu.

## Быстрый старт

Подготовьте поддерживаемый сервер Linux и выполните команду от имени root:

```bash
bash <(curl -fsSL https://github.com/hello-yunshu/Xray_bash_onekey/releases/latest/download/install.sh)
```

После установки выполните `idleleo`, чтобы открыть меню управления. Можно также сразу запустить `idleleo --install-reality`, `idleleo --install-tls` или `idleleo --install-none` для нужного режима.

При первом запуске следуйте мастеру установки и нажимайте Enter, чтобы принять значения по умолчанию для незнакомых параметров. После установки настройте клиент по ссылке для обмена или QR-коду, которые выведет скрипт.

## Режимы установки

| Режим | Сценарий | Ключевые особенности |
|---|---|---|
| Reality + Nginx | Рекомендуемая точка входа на одном сервере | При необходимости можно добавить простые протоколы ws/gRPC/xHTTP для балансировки |
| Nginx + TLS | Стандартная точка входа TLS | Автоматически запрашивает и продлевает сертификаты Let's Encrypt |
| ws/gRPC/xHTTP ONLY | Бэкенд или узел балансировки | Без TLS; по умолчанию слушает только `127.0.0.1` |
| Транзитный узел | Независимая переадресация TCP | Использует Nginx Stream для переадресации на одну цель и не устанавливает Xray |
| Docker | Контейнерное развёртывание | Образ содержит Xray, Nginx и основной скрипт |

При установке режима ws/gRPC/xHTTP выберите `ws`, `gRPC`, `xHTTP` или `ws+gRPC+xHTTP`. Скрипт создаёт порт, путь, ссылку для обмена и QR-код для каждого транспорта. Профили Clash пропускают xHTTP, и скрипт выводит предупреждение.

## Статистика трафика Xray

После включения статистики API статистики по умолчанию слушает только `127.0.0.1:10085`. Чтение выполняет отдельный скрипт `/etc/idleleo/scripts/xray_stats.sh` с правами `0600 root:root`. Основной скрипт отвечает только за точку входа, загрузку, проверку SHA256 и делегирование; он не дублирует логику запросов.

```bash
idleleo --stats                  # Таблица: входящий, исходящий и общий трафик по inbound
idleleo --stats --json           # Машиночитаемый JSON
idleleo --stats-reset            # Сброс счётчиков после интерактивного подтверждения
idleleo --stats-reset --yes      # Подтверждение для автоматизации
idleleo --stats-watch 5          # Обновление каждые 5 секунд; Ctrl-C завершает
```

Если скрипт статистики отсутствует, основной скрипт загружает `xray_stats.sh` из текущего Release и проверяет его по `statsScriptSha256` из `release-manifest.json`. Ошибка проверки влияет только на чтение, но не на переключатель статистики. Если статистика включена, но `api.listen` отсутствует, первый запуск `--stats` явно спрашивает, нужно ли добавить его и перезапустить Xray; отказ оставляет конфигурацию без изменений.

### Коды выхода

| Код выхода | Значение |
|---|---|
| `0` | Запрос выполнен; нулевые счётчики также считаются успехом |
| `1` | Пользователь отменил сброс |
| `2` | Нет обязательного условия: статистика выключена, нет `api.listen`, Xray не запущен, API недоступен, скрипт отсутствует или не прошёл проверку |
| `3` | Ошибка вызова API или разбора JSON |
| `4` | Неверные аргументы |
| `5` | Не root или недостаточно прав |
| `130` | Наблюдение прервано Ctrl-C |

При сбоях скрипт никогда не выводит ложный ноль: выключенная статистика или недоступный API возвращают `2`, неверный JSON — `3`, запуск не от root — `5`.

### Граница безопасности

> API статистики слушает только loopback, но не имеет аутентификации. Другие локальные пользователи теоретически могут обратиться к порту и прочитать или сбросить счётчики. Используйте его на VPS с одним пользователем и никогда не открывайте `10085` в интернет; `--stats-reset` всегда требует явного подтверждения.

Xray StatsService предоставляет только счётчики входящего/исходящего трафика по inbound и Uptime; он **не предоставляет число активных подключений**. Для числа подключений используйте системные инструменты или отдельное решение наблюдаемости, а не ждите его от `--stats`.

## Резервное копирование и восстановление

`idleleo --backup` сохраняет только файлы, управляемые скриптом: `/etc/idleleo`, `/usr/local/nginx`, бинарник Xray, unit-файлы systemd, crontab root и состояние ACME. Это не полная резервная копия хоста, и данные, размещённые в других местах, автоматически в неё не попадают.

`idleleo --restore` выбирает резервную копию с самой новой отметкой времени. Копии с манифестом контрольных сумм проверяют SHA256 каждого файла архива и удаляют управляемую конфигурацию, отсутствующую в копии; старые копии без манифеста проходят только структурную проверку и пропускают очистку между режимами. Пользовательские файлы сохраняются, службы автоматически не запускаются. После восстановления между режимами проверьте оставшуюся конфигурацию и при необходимости перезапустите службы. Если в старой резервной копии нет символической ссылки `/usr/local/share/xray`, восстановление создаёт её или объединяет старый каталог GeoData с `/etc/idleleo/share/xray`, затем проверяет реальным `xray run -test`; неудачное самовосстановление откатывается, поэтому старые копии по-прежнему восстанавливаются на новом хосте без переустановки.

Архивы резервных копий могут содержать сертификаты, закрытые ключи и клиентскую конфигурацию. Обращайтесь с ними как с конфиденциальными файлами и не загружайте их в публичные места.

## Обновление и обслуживание

Обновляйтесь через «Мастер обновления → Обновить скрипт» в меню управления или выполните:

```bash
idleleo --update                  # Интерактивное подтверждение
idleleo --update --yes            # Неинтерактивно, авто-подтверждение в той же серии выпусков
idleleo --update --yes --allow-major  # Обновление между сериями; явно снять ограничение
```

`--yes` автоматически подтверждает только обновления в той же серии выпусков; для перехода между сериями также нужен `--allow-major`. `--allow-major` только снимает ограничение серии и не заменяет подтверждение, поэтому в неинтерактивном режиме всё равно нужен `--yes`. Обновление скрипта целиком заменяет `/etc/idleleo/install.sh`, пересчитывает URL Release для нового скрипта и синхронизирует вспомогательные ресурсы.

`--xray-update` обновляет только ядро Xray, а `--nginx-update` — только Nginx; ни один из них не обновляет сам скрипт. Автоматическое обновление скрипта выполняется только в той же серии выпусков; автоматические обновления Xray и Nginx по-прежнему следуют метаданным API. Перед обновлением выполните `idleleo --backup`.

Устаревший режим XTLS больше не предлагает установку или переустановку. Существующие службы XTLS могут продолжать работать, но скрипт не может переустановить их или сменить режим. Для дальнейшего управления сначала создайте резервную копию и удалите их, затем разверните Reality, TLS или транзитный режим.

## Переконфигурация

При повторном запуске установщика на уже установленной системе он автоматически сохраняет текущую конфигурацию и предлагает три пути:

| Путь | Описание | Ограничение |
|---|---|---|
| Сохранить конфигурацию и переразвернуть | Сохраняет пользовательские routing, outbounds, DNS и многопользовательские настройки; изменяет только выбранные поля | Не поддерживает изменение структуры транспорта, например ws на gRPC |
| Пересобрать по стандартному шаблону | Создаёт стандартный шаблон из повторно используемых параметров | Пользовательские routing, outbounds и DNS могут быть удалены |
| Смена режима | Переход на другой режим протокола, например с Reality на TLS | По умолчанию повторно использует UUID/email только основного пользователя; остальные пользователи не переносятся |

Если какой-либо шаг завершается ошибкой (запись конфигурации, запуск службы, проверка состояния и т. д.), скрипт откатывается к сохранённой исходной конфигурации. Каталоги резервных копий используют уникальные отметки времени, поэтому повторные переконфигурации не конфликтуют.

## Менеджер Go (экспериментально, не включён)

Репозиторий уже содержит исходный код будущего менеджера Go и код моста миграции, но **текущий выпуск не предоставляет бинарник Go и не включает миграцию**:

- Новая установка, `-u`, полная переустановка, меню, `auto_update` и cron никогда не проверяют, не предлагают и не скачивают ресурсы Go и не отправляют запросы к манифесту bridge.
- Пока URL манифеста отсутствует, точка входа миграции не появляется; обычные пользователи не видят никаких опций Go.
- Единственная точка входа — явный параметр `--internal-bridge-offer`, предназначенный только для проверки сопровождающими и не доступный обычным пользователям.
- Менеджер Go будет явно включён только в более позднем выпуске, когда станет достаточно стабильным для переключения; до тех пор продолжайте использовать существующий Bash-скрипт управления.

## Диагностика

| Симптом | Что проверить сначала | Рекомендация |
|---|---|---|
| Установка отклонена | `/etc/os-release` и матрица поддерживаемых систем | Обновите систему до поддерживаемой версии или используйте Debian/Ubuntu |
| Xray не запущен | `systemctl status xray`, `idleleo --xray-error` | Проверьте `journalctl -u xray`, конфигурацию и занятость портов |
| Ошибка синтаксиса конфигурации | `xray run -test -config /etc/idleleo/conf/xray/config.json` | Исправьте ошибку или откатитесь через `idleleo --restore` |
| Порт уже занят | `ss -ltnp` | Освободите порт или измените порт прослушивания в меню |
| Проблема с сертификатом | `idleleo --cert-status` | Проверьте DNS, порты 80/443 и состояние ACME, затем выполните `idleleo --cert-update` |
| Конфликт с существующим Nginx | `/usr/local/nginx/sbin/nginx -V`, `systemctl status nginx` | Не смешивайте с Nginx, установленным LNMP или похожими скриптами; сначала устраните конфликт |
| Статистика возвращает `2` | Переключатель статистики, состояние Xray, `127.0.0.1:10085` | Включите статистику, запустите Xray или проверьте `api.listen` |
| Статистика возвращает `3` | Ответ API и структура JSON | Проверьте журналы и конфигурацию Xray, убедитесь, что StatsService доступен |
| Статистика возвращает `5` | Текущий пользователь | Запустите от root или проверьте права на файлы |
| В Clash нет узлов | Тип протокола | Clash не поддерживает xHTTP; используйте совместимый клиент |

Журналы и диагностика: `/etc/idleleo/logs/`, `/var/log/xray/`, `idleleo --show`, `idleleo --xray-access` и `idleleo --xray-error`.

## Частые вопросы

**Может ли статистика показывать число активных подключений?** Нет. StatsService предоставляет только счётчики входящего/исходящего трафика по inbound и Uptime; число подключений он не даёт.

**Когда пользователям Cloudflare включать CDN?** Включайте CDN только после проверки установки, сертификатов и прямого подключения. Иначе прокси CDN может помешать выпуску сертификатов.

**Можно ли использовать IPv4 и IPv6 одновременно?** Да. Скрипт определяет возможности публичного исходящего трафика и отдельно проверяет записи A/AAAA домена. В среде с двойным стеком настройте корректные записи A и AAAA.

**Как изменить порт, UUID или транспорт?** Откройте «Изменение конфигурации» в меню или повторно запустите мастер установки и выберите путь переконфигурации. Для изменения структуры транспорта используйте пересборку по стандартному шаблону.

**Как удалить?** Выполните `idleleo --purge`. Перед удалением выполните `idleleo --backup` и решите, нужно ли сохранять конфигурацию и сертификаты.

**Какие требования к сопоставлению произвольной строки с UUID?** Скрипт использует сопоставление UUIDv5, которое требует поддержки на стороне клиента. Если клиент её не поддерживает, используйте стандартный UUID.

**Можно ли сразу использовать в продакшене?** Сначала проверьте в тестовой среде подключение, продление сертификатов, резервное копирование/восстановление и путь обновления, и только затем используйте в продакшене.

## Безопасность

- API статистики слушает только `127.0.0.1` и не имеет аутентификации. Не открывайте `10085` в интернет и не допускайте к нему недоверенных локальных пользователей.
- Режим Reality + Nginx по умолчанию включает SNI Guard: неизвестный SNI, пустой SNI и аномальный TLS никогда не попадают в бэкенд Xray Reality; по умолчанию используется изоляция `ssl_reject_handshake`.
- Fail2ban, межсетевой экран и блокировка трафика — необязательные средства усиления. Перед включением убедитесь, что они не заблокируют ваш собственный доступ к управлению.
- Архивы резервных копий, сертификаты и клиентская конфигурация содержат конфиденциальные данные. Ограничьте права на файлы и не публикуйте их.
- Скрипту нужен root; не используйте его в продакшене до проверки работоспособности.

## Docker и AI Skill

Образ Docker содержит Xray, Nginx и основной скрипт; функции исходного скрипта доступны внутри контейнера. См. [руководство по развёртыванию Docker](https://github.com/hello-yunshu/Xray_bash_onekey/blob/main/docker/DOCKER.md).

```bash
git clone https://github.com/hello-yunshu/Xray_bash_onekey.git
cd Xray_bash_onekey
docker compose up -d
docker attach xray-onekey
```

AI Skill позволяет AI-инструменту с поддержкой Skills выполнить развёртывание автоматически, без ответов на каждый интерактивный вопрос. См. [Xray_bash_onekey_skill](https://github.com/hello-yunshu/Xray_bash_onekey_skill).

Скрипт поддерживает Reality, TLS, ws/gRPC/xHTTP ONLY и транзитный узел Nginx Stream. Шаблоны автоматического развёртывания AI Skill сейчас покрывают только Reality и TLS; для ws/gRPC/xHTTP ONLY и транзитного узла используйте idleleo на сервере.

## Помощник эксплуатации RillML Xray AI

RillML (сокращённо Rill) обеспечивает локальную адаптивную эксплуатацию Xray: мониторинг состояния Xray/Nginx в реальном времени, автоматическую диагностику сбоев и рекомендации по устранению без внешнего API. Введите `9` в главном меню или выполните `idleleo --rill-agent`.

| Действие | Команда |
|---|---|
| Открыть меню AI-помощника | `idleleo --rill-agent` |
| Установить или восстановить движок AI-решений | `idleleo --rill-agent-install` |
| Показать состояние AI-решений | `idleleo --rill-agent-status` |
| Запустить AI-диагностику | `idleleo --rill-agent-diagnose` |
| Проверить движок AI-решений | `idleleo --rill-agent-verify` |
| Безопасно отключить AI-решения | `idleleo --rill-agent-safe-disable` |
| Удалить движок Rill AI | `idleleo --rill-agent-uninstall` |

По умолчанию Rill ориентирован на диагностические рекомендации и не изменяет систему до включения автоматических изменений.
