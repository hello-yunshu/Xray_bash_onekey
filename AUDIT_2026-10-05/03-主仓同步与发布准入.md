## XRA-06 · P1 · GeoData 更新可虚报成功或留下不能回滚的损坏数据

定位：`scripts/geo_update.sh:70–88、103–138；set_local_version:58–67`。

审计证据：已复现：函数内 mv 返回 1，download_geo_file 仍显式 return 0。静态路径还显示：仅检查文件非空、逐个直接替换 geoip/geosite、更新 version 后才 restart；第二个文件/重启失败不恢复首个/旧文件。URL 是 latest/download，先读取 tag 后发生 release 变化时，版本与字节也可能错配。

### 必须实现

1. 使用发现的 immutable tag URL 下载本轮 geoip/geosite，两者同一 release；获取并验证上游摘要/可信 release metadata，非空不是有效 DAT。
2. 所有 mv、version JSON 写入/rename 和 restart 错误必须传播，日志不能在失败后写 updated successfully。
3. 两份数据和 version metadata 在 staging 核验，使用 Xray 实际配置 parse/test 校验候选数据；需要时设置临时资产路径，不能直接覆盖运行资产再试错。
4. 保留 previous-good 两份文件及 metadata，切换后 restart/active/必要健康检查失败时恢复并验证服务；错误状态与“已恢复服务”分别表示。
5. 与手动 geo 更新/Xray 更新共享适当锁，保留正常 disabled/inactive 服务状态。限定网络和总执行时限，不能年龄超时就删除仍被活进程持有的锁。
6. 若上游无法提供可靠摘要，需要明确记录受 HTTPS 信任边界而非宣称已验签；仍实现真实 DAT 和事务校验。

### 验收测试

- mv 返回 1 时函数非零；jq/mv version metadata 失败也非零并保持旧版本。
- 第二个文件下载失败、HTML 非空、坏 DAT、hash 错、restart/health 失败：两份文件和 metadata 都恢复。
- 发现 tag 后 latest 改变，仍只用发现的 tag；不会 vA 标签安装 vB 字节。
- 并发自动/手动更新不交错；旧 inactive 服务不被擅自启用。正常更新只做必要一次 restart。

## XRA-10 · P1 · Shell Release 没有绑定完整 Linux 资格的准入门

定位：`.github/workflows/publish-shell-version.yml 的 Validate release candidate / Create or verify immutable Release；test-install.yml、rill-xray-agent.yml`。

审计证据：静态确认：手动 release 工作流在 bash -n 和 9 个 release-automation 单元测试后即可创建生产 Release，再更新 API；没有 needs/查询/证据绑定，要求该 candidate exact SHA 的 Linux 安装回滚、Rill canonical 和真实 PID1 qualification 全部成功。主仓库其它 CI 独立运行不能保证手动发布准入。未在远端验证或创建 Release。

### 必须实现

1. 在任何 gh release create/tag/upload/API 写入前，运行或获取该 candidate exact SHA 的可信资格证据：完整安全回归、支持发行版安装升级恢复矩阵、固定 canonical digest/bundle、模式/DAC/真实 PID1 验证。
2. 优先 reusable qualification workflow 由 release 调用并 needs 成功；若消费历史 run，严格检查 repo/workflow identity/head_sha/conclusion、必需 jobs/矩阵和 artifact digest。不能只接受任意 latest success 或 source SHA 不同的 main。
3. 将 qualification run id、SHA、资产摘要/canonical pin 写进 Release manifest。待上传 install.sh/bundle bytes 必须与通过资格的 bytes 一致。
4. 未完成、失败、缺矩阵、缺 evidence 或 SHA 不同均 fail-closed。已有 immutable Release 重跑也检查 tag->candidate、assets identity 和资格；不能补写同版本不同字节。
5. API promotion 最后发生；发布失败不提前推进在线版本。保留现有 exact installer ref+hash 和 version API 两文件 tested/online 同步规则。
6. 保持只读 workflow 最小权限，写 token 限定最终 job；不要在 PR 来源代码执行时暴露 release token。

### 验收测试

- 某个 qualification job/矩阵失败、pending、缺 evidence、wrong SHA：release/tag/upload/API 全零调用。
- old successful main run 不能为新 candidate 提供资格；同 SHA 但不同 bundle hash 也拒绝。
- 全资格通过只发布验证的资产，记录 run/SHA/digest；重复同版本同字节幂等，同版本不同字节拒绝。
- 上游 API 独立 candidate qualification 流程继续保留；本阶段关注 shell Release，不把 API 的 Xray core installer 资格替代全部 shell 资格。
