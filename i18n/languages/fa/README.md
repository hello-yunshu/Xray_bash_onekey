## ویژگی‌های عملکردی

* ورود`idleleo`منوی مدیریت Xray را باز کنید تا نصب‌ها، خدمات، تنظیمات امنیتی و غیره را مدیریت کنید.
* از Qwen-MT-Plus AI برای ترجمه دقیق چندزبانه استفاده می‌شود.
* از پروتکل Reality پشتیبانی می‌کند، توصیه می‌شود با Nginx همراه شود (قابل نصب در اسکریپت)
* پشتیبانی از انتقالات WebSocket، gRPC و xHTTP با امکان انتخاب یک انتقال واحد یا`ws+gRPC+xHTTP`همزمان فعال کنید
* پشتیبانی از دو ستک IPv4 / IPv6: در زمان نصب، می‌توان ظرفیت خروج از شبکه عمومی را به صورت خودکار شناسایی کرد و بر اساس نام دامنه A/AAAA، گزارش‌های مستقلی ثبت و پیوندهای به اشتراک‌گذاری متناظر و تنظیمات Clash تولید می‌شود.
* محافظت داخلی fail2ban (قابل نصب درون اسکریپت)
* در Xray داخلی، آمار ترافیک، مسدود کردن ترافیک، به‌روزرسانی قوانین GeoIP/GeoSite و به‌روزرسانی زمان‌بندی شده وجود دارد.
* پشتیبانی از نسخه‌برداری و بازگردانی در صورت شکست برای به‌روزرسانی‌های کلیدی، همچنین پشتیبانی از اسکریپت‌ها، Xray، Nginx و به‌روزرسانی گواهی‌نامه‌ها
* قبل از بازنصب و تغییر حالت، تنظیمات جاری به صورت خودکار پشتیبان گرفته می‌شوند و در صورت شکست، تنظیمات اصلی بازیابی می‌شوند.
* بازآرایی سه مسیر امن فراهم می‌کند: بازنشر پیکربندی حفظ شده، بازسازی الگوی استاندارد و تغییر وضعیت
* استفاده از[@DuckSoft](https://github.com/DuckSoft)لینک به اشتراک‌گذاری[پیشنهاد](https://github.com/XTLS/Xray-core/issues/91)(beta)، سازگار با Qv2ray، V2rayN، V2rayNG
* استفاده از[XTLS](https://github.com/XTLS/Xray-core/issues/158)پیشنهاد، دنبال کردن[UUIDv5](https://tools.ietf.org/html/rfc4122#section-4.3)معیار، پشتیبانی از نقشه‌گذاری رشته‌های سفارشی به VLESS و UUID
* پروتکل gRPC را پشتیبانی می‌کند:[از پروتکل gRPC استفاده کنید](https://hey.run/posts/xrayjin-jie-wan-fa---shi-yong-grpcxie-yi)
* پشتیبانی از باراندازی Reality / ws/gRPC/xHTTP:
  - [توزیع بار Reality در REALITY](https://hey.run/posts/bushu-reality-balance)
  - [ساختن توزیع‌کننده بار پشتی](https://hey.run/posts/xrayjin-jie-wan-fa---da-jian-hou-duan-fu-wu-qi-fu-zai-jun-heng)
* Reality + Nginx حالت پیش‌فرض فعال است SNI Guard: ناشناخته SNI، خالی SNI و بطور غیرعادی TLS به پشتیبان Xray Reality وارد نمی‌شوند، پیش‌فرض از روش جداسازی ( ssl_reject_handshake) استفاده می‌شود؛ کاربران پیشرفته می‌توانند به سایت بازگشتی decoy ساخته شده توسط خود یا مستقیماً از طریق TCP رد کنند. این ویژگی برای کاهش کشفِ فعال و آشکار شدن تنظیمات نادرست استفاده می‌شود و به دنبال نقاب زدن کامل نیست.

## عملیات آماده سازی

* یک سرور خارج از کشور با دسترسی به شبکه عمومی IP
* برنامه‌نویسی پروتکل Reality را نصب کنید: باید یک دامنه هدف مطابق با Anhui Xray آماده کنید.
* نصب نسخهٔ TLS: باید یک دامن از پیش آماده کرد و بر اساس شبکهٔ در دسترس سرور، رکورد‌های A و/یا A را به درستی تنظیم کرد؛ در محیط دوگانه (دوپروتکلی) توصیه می‌شود همزمان A و A به درستی تنظیم شوند. اسکریپت امکان تشخیص خودکار قابلیت شبکهٔ IPv4/IPv6 را دارد و در صورت وجود شبکهٔ دوگانه، می‌تواند همزمان ورودی‌های مربوط به کلاینت را ایجاد کند.
* خواندن[Xray مستندات رسمی](https://xtls.github.io)، مفاهیم مربوط به Reality، TLS، WebSocket، gRPC و Xray را در REALITY بفهمید
* **مطمئن شوید که curl نصب شده است**: توسط کاربر CentOS اجرا شود`yum install -y curl`؛Debian/Ubuntu کاربر اجرا می‌کند`apt install -y curl`

## حالت نصب

| حالت طرح | توضیح |
|------|------|
| Reality + Nginx | حالت توصیه‌شده، می‌تواند به صورت نیاز ws/gRPC/xHTTP پروتکل ساده را برای تعادل بار اضافه کند. |
| Nginx + TLS | پشتیبانی از ws/gRPC/xHTTP، درخواست خودکار و تمدید گواهینامه Let's Encrypt |
| ws/gRPC/xHTTP ONLY | در حالت ورودی مستقل بدون TLS، از آن بیشتر در سناریوهای پشتیبان یا توزیع بار استفاده می‌شود. |
| گره میانبر | نقش سرور مستقل، تنها از Nginx Stream برای رله TCP تک هدفه استفاده می‌شود و Xray نصب نمی‌شود. |
| Docker | در تصویر آینه‌ای، Xray و Nginx به همراه اسکریپت اصلی پیش‌نصب شده است. |

هنگام نصب رژیم مربوط به ws/gRPC/xHTTP، می‌توانید انتخاب کنید`ws`, `gRPC`, `xHTTP`یا`ws+gRPC+xHTTP`اسکریپت به ترتیب پورت‌ها، مسیرها، لینک‌های اشتراک‌گذاری و کدهای QR را ایجاد می‌کند؛ در حال حاضر Clash از xHTTP پشتیبانی نمی‌کند و اسکریپت در خروجی تنظیمات به این موضوع اشاره خواهد کرد.

## توضیحات بازتنظیم

وقتی محیط نصب‌شده دوباره اجرا می‌شود، فایل اسکریپت به‌طور خودکار پشتیبان کنفیگوراسیون فعلی را می‌گیرد و سه گزینه برای بازتنظیم ارائه می‌دهد:

| مسیر | توضیح | محدودیت |
|------|------|------|
| پیکربندی را برای بازنشر نگه دارید | routing/outbounds/DNS سفارشی و تنظیمات چند کاربره را حفظ کنید، فقط موارد انتخاب شده توسط کاربر (پورت‌ها، مسیرها، پارامترهای UUID و Reality و غیره) را تغییر دهید. | تغییرات ساختار انتقال (مانند ws → gRPC) پشتیبانی نمی‌شود؛ برای تغییر ترکیب انتقال، لطفاً با استفاده از قالب استاندارد دوباره ایجاد کنید. |
| بازسازی الگوی استاندارد | با استفاده از پارامترهای قابل استفاده مجدد فعلی، تنظیمات قالب استاندارد ساخته می‌شود و routing/outbounds/DNS سفارشی شده ممکن است حذف شود. | تعداد کاربران الزامی نیست که ثابت بماند. |
| تغییر حالت | به حالت‌های مختلف پروتکل سوئیچ کنید (مثلاً Reality → TLS)، به طور پیش‌فرض فقط از کاربر اصلی UUID/email استفاده مجدد می‌شود. | کاربران دیگر به صورت خودکار منتقل نمی‌شوند و قبل از تغییر، پیام واضحی نشان داده می‌شود. |

هرگونه شکست در هر مرحله از فرآیند بازتنظیم (مانند نوشتن تنظیمات، راه‌اندازی خدمات، بررسی سلامت و غیره) به طور خودکار به تنظیمات اصلی پشتیبان بازگردانده می‌شود. دایرکتوری پشتیبان از یک تاریخ‌نگار منحصر به فرد استفاده می‌کند، که امکان بازتنظیم مکرر و بدون تداخل را فراهم می‌آورد.

## توضیحات به‌روزرسانی

### 3.2.9 / 3.2.10 / 3.2.11 → 3.3.x

به‌روزرسانی خودکار برای Shell در سراسر minor اعمال نمی‌شود؛`idleleo --update auto_update`به طور واضح پرش خواهد کرد و حفظ می‌شود
نسخه‌ی قدیمی است و گزارش موفقیت را بی‌صدا انجام نمی‌دهد. لطفاً از روش به‌روزرسانی دو مرحله‌ای تعاملی استفاده کنید:

```bash
bash /etc/idleleo/install.sh --update          # 交互终端，选择 Y
bash /etc/idleleo/install.sh --xray-update     # 再更新 Xray
```

محیط خودکار باید به طور صریح تأیید شود:

```bash
bash /etc/idleleo/install.sh --update --yes                  # 同一 minor
bash /etc/idleleo/install.sh --update --yes --allow-major    # 跨 minor
```

`--yes`فقط به‌طور خودکار به‌روزرسانی یکسان minor را تأیید می‌کند؛ برای فراتر از minor نیازمند اضافه کردن صریح است.`--allow-major`.
`--allow-major`فقط محدودیت عبور از minor را بر می‌دارد، خودش جایگزین تأیید Y/N نمی‌شود (در صحنه‌های غیر تعاملی همچنان نیاز است)
همزمان به`--yes`). پیش از به‌روزرسانی، توصیه می‌شود ابتدا انجام شود`idleleo --backup`؛3.3.1 اختیارات فایل پشتیبانگیری شروع می‌شود
برای 0600.

### 3.3.0 → 3.3.1

در منوی مدیریت «راهنمای به‌روزرسانی → پیاده‌سازی فایل به‌روزرسانی» به‌روزرسانی کنید یا این دستور را اجرا کنید:

```bash
bash /etc/idleleo/install.sh --update
```

3.3.1 اصلاح باقی‌مانده‌های غیرفعال‌سازی آفلاین، مجوزهای پشتیبان‌گیری/روزمره، اصلاحات ناقص Xray و ثبت هویت شکست‌خورده installer
Shell جلوگیری از بازگشت متادیتا. به‌روزرسانی پیکربندی موجود Xray را تغییر نمی‌دهد؛ REALITY`minClientVer`تکمیل همچنان طبق
اجرای قوانین 3.3.0.

3.3.1 باقی ماندن شماره نسخه در توزیع مجدد. گره‌های قدیمی که 3.3.1 را نصب کرده‌اند از طریق 3.3.1 جدید به روز نخواهند شد.`-u`به طور خودکار نصب کننده جدید را دریافت کنید
(نسخه‌های یکسان به عنوان نسخه جدید در نظر گرفته می‌شوند)؛`-x`فقط هسته Xray به‌روزرسانی می‌شود، اما پیکربندی Shell به‌روزرسانی نمی‌شود. وقتی بسته جدید لازم است،
لطفاً دوباره نصب کنید یا به صورت دستی جایگزین کنید`/etc/idleleo/install.sh`.

### حالت XTLS نسخه‌ی قدیمی

از نسخه 3.3.0، حالت قدیمی XTLS حذف شده است. خدمات موجود XTLS پس از به‌روزرسانی همچنان قابل اجرا خواهند بود، اما دوباره نصب آنها از طریق اسکریپت ممکن نخواهد بود و
حالت را تغییر دهید؛ برای ادامه مدیریت، لطفاً ابتدا پشتیبان بگیرید و حذف کنید، سپس مجدد حالت میانبر Reality/TLS/ را در REALITY نصب کنید.

### به‌روزرسانی خودکار

به‌روزرسانی خودکار تنها در همان minor Shell را به‌طور خودکار به‌روز می‌کند؛ برای عبور از minor، باید دو مرحله فوق را به‌صورت دستی انجام داد. Xray و
به‌روزرسانی خودکار Nginx همچنان بر اساس متادیتای API انجام می‌شود؛ رکوردهای شکست‌خورده شامل`component`, `version`, `installer_ref`, `installer_sha`با`failed_at`فیلدها (به ترتیب نشان‌دهنده کامپوننت، نسخه هدف، مرجع installer، تابع‌گشا installer و زمان شکست).

## RillML Xray دستیار عملیات و نگهداری AI

RillML (به اختصار Rill) توانمندی‌های عملیات و نگهداری هوشمند سازگار با محل را برای Xray فراهم می‌کند.

یک کمک‌کننده Nginx مدیریت و نگهداری AI محلی درون‌ساز وجود دارد که وضعیت سلامت Xray/Nginx را به‌صورت زنده overwach می‌کند، خرابی‌ها را به‌طور خودکار تشخیص می‌دهد و پیشنهادات برای رفع مشکل ارائه می‌دهد، بدون نیاز به API بیرونی. در منوی اصلی وارد کنید`9`یا اجرا کنید`idleleo --rill-agent`وارد شوید.

**قدرت اصلی**

* نظارت: مشاهدهٔ وضعیت خدمات و تنظیمات Xray/Nginx به‌صورت زنده
* تشخیص: تعیین علت اصلی خطا، با پیشنهاد سطح اطمینان (بالا / متوسط / پایین / شواهد ناکافی)
* تشخیص: نوع خطا به صورت خودکار تشخیص داده می‌شود و پیشنهادات برای رفع آن ارائه می‌گردد؛ در توضیحات به طور واضح مشخص شده است که عملیات خودکار مجاز است یا تنها پیشنهاد داده می‌شود.
* حالت: تشخیص هوشمند / تنها مشاهده / غیرفعال سازی ایمن، تا قبل از فعال کردن تغییرات خودکار، سیستم تغییر نخواهد کرد.

**دستورات رایج**

| عملیات | دستور |
|------|------|
| منوی کمک‌رسان عملیاتی AI را باز کنید | `idleleo --rill-agent` |
| نصب یا اصلاح موتور تشخیص AI | `idleleo --rill-agent-install` |
| AI وضعیت تشخیص را بررسی کنید | `idleleo --rill-agent-status` |
| اجرای تشخیص خطا با AI | `idleleo --rill-agent-diagnose` |
| گشت و خدمت موتور تشخیص AI | `idleleo --rill-agent-verify` |
| تصمیم گیری در مورد توقف ایمن AI | `idleleo --rill-agent-safe-disable` |
| Rill موتور AI را حذف کنید | `idleleo --rill-agent-uninstall` |

موتور تشخیص AI هنوز در مرحله آزمایشی است، توصیه می‌شود بیشتر به پیشنهادات تشخیصی اعتماد کرد و به طور پیش‌فرض سیستم به صورت خودکار تغییر نمی‌کند.

## Deploy Docker

پشتیبانی از استفاده از Docker برای نصب، با عکس‌های پیش‌نصب شدهٔ Xray و Nginx، درون حاويه می‌توان از تمام قابلیت‌های فایل‌های اسکریپت اصلی مستقیماً استفاده کرد. جزئیات را ببینید[دستورالعمل نصب Docker](/docker/DOCKER.md).

```bash
git clone https://github.com/hello-yunshu/Xray_bash_onekey.git
cd Xray_bash_onekey
docker compose up -d
docker attach xray-onekey
```

## پیاده‌سازی AI Skill

از طریق ابزارهای AI (مانند Trae) پشتیبانی می‌شود تا به صورت خودکار Xray را نصب کند، بدون نیاز به تعامل دستی. جزئیات بیشتر در[Xray_bash_onekey_skill](https://github.com/hello-yunshu/Xray_bash_onekey_skill).

روش سنتی نیازمند این است که SSH به سرور بروید، فایل‌های نصب را اجرا کنید و به پرسش‌های تعاملی یکی پس از دیگری پاسخ دهید؛ در حالی که با روش Skill فقط باید به AI نیاز خود را بگویید، AI یک فایل نصب غیرتعاملي تولید می‌کند و آن را اجرا کرده و مستقیماً لینک VLESS را بر می‌گرداند.

**حالت پشتیبانی**: Reality / TLS / ws ONLY / گره میانبر

**استفاده**: در ابزارهای AI پشتیبانی‌کننده از Skill، مستقیماً بگویید "در سرور من Xray را نصب کنید"، AI به طور خودکار اطلاعات را جمع‌آوری می‌کند، یک فایل اسکریپت تولید می‌کند، نصب را اجرا می‌کند و اطلاعات اتصال را بر می‌گرداند.

## نکات مورد توجه

* وقتی معنای تنظیمات مختلف را نمی‌دانید، به جز موارد الزامی از مقادیر پیش‌فرض استفاده کنید (فقط در تمام مراحل دکمه Enter را فشار دهید).
* Cloudflare کاربر لطفاً پس از تکمیل نصب CDN را فعال کند
* این اسکریپت نیازمند مبانی Linux و دانش عمومی شبکه‌های کامپیوتری است.
* پشتیبانی می‌شود از Debian 12+ / Ubuntu 24.04+ / CentOS Stream 10+، برخی قالب‌های CentOS ممکن است مشکلات کامپایل داشته باشند، توصیه می‌شود در صورت بروز مشکل از سیستم عامل جدیدتر استفاده کنید.
* پیشنهاد می‌شود که فقط یک پیوندگر در هر سرور نصب شود و از پورت پیش‌فرض ۴۴۳ استفاده شود.
* نقش‌گذاری رشته سفارشی بر روی UUIDv5 نیازمند پشتیبانی کلاینت است.
* توصیه می‌شود در محیطی خالص استفاده شود؛ افراد جدید وارد نشوند CentOS
* این برنامه به Nginx وابسته است، که از طریق گذشته شده است.[LNMP](https://lnmp.org)کاربرانی که پیش‌تر Nginx را نصب کرده‌اند، لطفاً به تعارضات احتمالی توجه کنند.
* xHTTP پیوند به اشتراک‌گذاری برای کلاینت‌های پشتیبانی‌کننده از xHTTP مناسب است؛ تنظیمات خروجی Clash باعث می‌شود که xHTTP نادیده گرفته شود
* قبل از تأیید قابلیت استفاده، این فایل اسکریپت را در محیط تولید استفاده نکنید.
* نویسنده: یون شو، فقط پشتیبانی محدود ارائه می‌دهد

## سپاسگزاری

* بر اساس[wulabing/V2Ray_ws-tls_bash_onekey](https://github.com/wulabing/V2Ray_ws-tls_bash_onekey)توسعه
* TCP نسخه‌برداری از اسکریپت تسریع شده از[ylx2016/Linux-NetSpeed](https://github.com/ylx2016/Linux-NetSpeed)

## پیکربندی گواهینامه

**گواهی سفارشی**: فایل‌های crt و key را به ترتیب با این نام‌ها نامگذاری کنید`xray.crt`و`xray.key`، وارد کنید`/etc/idleleo/cert`فهرست (اگر فهرست وجود ندارد، ابتدا آن را ایجاد کنید). لطفاً به مجوزها و مدت اعتبار گواهینامه توجه کنید؛ پس از انقضاء مدت اعتبار گواهینامه سفارشی، باید خودتان تمدید آن را انجام دهید.

**گواهی خودکار**: اسکریپت پشتیبانی از تولید خودکار گواهی Let's Encrypt (با مدت اعتبار ۳ ماه) را دارد و از نظر تئوری، پشتیبانی از تمدید خودکار را نیز دارد.

## Xray معرفی

* Xray یک ابزار باز و عالی برای پروکسی اینترنت است که از تمام پلتفرم‌ها از جمله Windows، macOS، Android، iOS و Linux پشتیبانی می‌کند.
* این اسکریپت یک اسکریپت تنظیم کامل یک‌کلیک است؛ پس از اتمام تمام مراحل به درستی، بر اساس نتایج خروجی، فقط کافی است کلاینت را تنظیم کنید تا بتواند استفاده شود.
* **به شدت توصیه می‌شود** که به طور کامل با جریان کار و اصول عملکرد برنامه آشنا شوید.

## مدیریت خدمات

| عملیات | دستور |
|------|------|
| راه‌اندازی Xray | `systemctl start xray` |
| توقف Xray | `systemctl stop xray` |
| راه‌اندازی Nginx | `systemctl start nginx` |
| توقف Nginx | `systemctl stop nginx` |

## دایرکتوری مربوطه

| محتوا | مسیر |
|------|------|
| دایرکتوری اصلی | `/etc/idleleo` |
| تنظیمات Xray | `/etc/idleleo/conf/xray/config.json` |
| تنظیمات Nginx | `/etc/idleleo/conf/nginx/` |
| اطلاعات نصب | `/etc/idleleo/conf/install_config.json` |
| پرونده گواهی | `/etc/idleleo/cert/xray.key`, `/etc/idleleo/cert/xray.crt` |
| دیرکتوری روزنامه | `/etc/idleleo/logs/`, `/var/log/xray/` |
| Nginx پوشه نصب | `/usr/local/nginx` |
| دستور مدیریت | `/usr/bin/idleleo` |
