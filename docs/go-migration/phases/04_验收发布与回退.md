# Phase 04｜实机验收、正式发布切换与旧用户回退保障

**阶段性质：** 以已完成的 Phase 00–03 为候选，完成可审计的真实 Linux 服务与迁移门禁；**不是**首次发现大问题才开始补所有测试。除明确发布许可外，不自动操作真实用户 VPS。

## 0. 发布目标

- 用 Go 完整替代 Bash 的**日常管理**，而不是仅仅替代入口文件。
- 用户通过一个 `idleleo` Go 程序管理 Xray/独立 relay，无额外 Web、管理端口、Go daemon/数据库；旧 Bash 不参与正常业务。
- Xray/Nginx、证书、用户、Rill、GeoData、ACL、Docker 主要功能和脚本调用方式没有未经批准的倒退。
- 自动更新不会把 Bash 用户无确认地切到 Go；迁移的失败/断电/停服问题可以识别、回退或提供准确人工修复。

## 1. 建立完整发布证据清单

由 Phase 00 的 F01–F28 + R01–R24 风险矩阵按下面表格逐条填写，**每项都有具体命令、环境、时间、Git commit、结果和日志**，不能只写“测试通过”。

| 证据组 | 内容 | 合格门槛 |
|---|---|---|
| 代码质量 | `go test ./...`、`go vet ./...`、必要的 race、安全扫描、依赖固定 | 无高风险未解释问题，源码和构建 SHA 可追溯 |
| CLI/只读 | --help、status、--show、--stats --json、所有硬兼容旧 flags | 离线、无 TTY、非 root/Root 的适用语义和退出码正确 |
| Xray 配置 | Reality/TLS/ONLY、单/组合传输、主次负载均衡 | 目标 `xray run -test`、真实服务启动/停止与重启后状态一致 |
| relay | 只运行 Nginx Stream，目标/监听修改、卸载与恢复 | 真实 TCP 字节级转发 + 无 Xray 依赖 |
| 安全 | 不改全局 SELinux/limits、权限、SNI、Fail2ban、cron、防火墙 | 高风险写入自有边界内、不泄露私钥 |
| 变更恢复 | 用户增删、UUID/shortId、端口、TLS、Nginx、GeoData、证书 | 候选失败、服务失败、断网中恢复正确原状态 |
| 备份 | hash、路径白名单、拒绝恶意归档、不同模式恢复 | 原用户文件不丢，错误恢复不误报成功 |
| Rill | 安装/缺失、观察、授权、回收/两阶段卸载 | Go 无强制依赖，Rill 状态不漂移 |
| Docker | 容器 fake-systemctl 兼容、entrypoint、volumes、自动看护 | 真实镜像构建并运行；不误操作宿主服务 |
| 迁移 | 老 Bash 不同版本、TTY 授权、拒绝/强杀/重启后恢复 | 成功与失败后都只有一个正式管理器 |
| 发行 | 双 metadata、Bash Release、Go Release、Bridge Release、manifest | 已验证独立；完整下载与 hash/来源匹配 |

## 2. 小而有效的实机矩阵

不要求同一模式在所有发行版与 CPU 上重复几十次，但**对每个声称支持的环境必须做相应级别的验证**：

| 维度 | 代表环境 | 需要的证据 | 未满足时怎么办 |
|---|---|---|---|
| 常用 Linux | Debian 12/13、Ubuntu 24.04/26.04 | OS 检测、二进制运行、安装/诊断基本路径 | 对未跑的发行版标暂不验证 |
| RPM Linux | CentOS Stream 10、Rocky/AlmaLinux 10+ | 安装方式、权限/SELinux Enforcing、服务 | 未跑实机不得声称“完全通过” |
| CPU | amd64、arm64 | 编译、运行与 Nginx 发布包实际匹配 | 仅编译不等于执行，标注缺口 |
| 安装模式 | Reality、TLS、ONLY、Reality primary/secondary、relay | 每个核心模式至少有一次真实内核/入口验证 | 对没有跑的模式拒绝宣称功能完整 |
| 用户数据 | 单/多用户、自定义 DNS/routing/outbounds、IPv6、证书 | 修改、重装、迁移 hash/语义对照 | 失配就阻断迁移，不自动修 |
| 运行环境 | 原生 systemd、Docker 假 systemctl | 分开验证，避免容器结果替代宿主机 | Docker 独立延后发布需明确标注 |
| 更新源 | 可达、超时、错误 SHA、旧版本、新版本 | 不降级、失败保留原内核/管理器 | 版本信息不可信则不升级 |

**建议执行顺序：** Debian 12/13 amd64 作为全面功能主环境 → Ubuntu 24.04 核查历史 Stats 失败 → CentOS Stream 10 验证权限/SELinux → Ubuntu 26.04/Rocky/Alma 的兼容检查 → arm64 实机/同架构云实例 → Docker。未覆盖项进入 Release Note，不能补写假日志。

## 4. 三组必须真实执行的故障验证

### A. 代理运行安全

1. 生成错误 Xray JSON、Nginx 配置、端口占用、权限错误；所有失败均不能破坏原已运行服务。
2. User add/remove 中间阶段注入错误，原 UUID、shortId、spiderX、多用户与服务状态保持；在支持协议中测试真实客户端握手（仅在合规可控测试环境）。
3. 证书未变化的续期只做必要检查，不多次重启；真正证书变化后验证权限和服务使用的新证书。
4. 自定义 `routing/dns/outbounds` 和额外 include 不能因普通修改消失；如无安全编辑方案则应拒绝，而不是自动恢复标准模板。
5. GeoData 自定义配置不覆盖，原生热更新不导致持续重启；SELinux 不被默认禁用。

### B. 管理与恢复

1. Xray/Go/Nginx 下载中断、SHA 错误、低磁盘、更新中断、内核二进制损坏，必须确认保留旧版本或输出 `RECOVERY_REQUIRED`。
2. 恶意备份：绝对路径、`../`、符号链接指向外部、重复路径、硬链接/设备条目、大量小文件，全部在危险写入前拒绝。
3. Fail2ban 含第三方 jail、root crontab 含额外任务、防火墙含同端口用户规则，安装、卸载和回滚前后差异必须可解释；绝不能粗暴 `*.local` 删除。
4. `--help`、status、show、统计只读行为利用截获 syscall/文件系统快照或功能等价办法证明零系统写入、零网络依赖。

### C. 跨版本迁移和恢复

1. **新安装 Go**：真机安装、再次安装、卸载、重新启动、更新、断网查询。
2. **老用户迁移**：Bash v3.3.4 和选定更早版本；Reality、TLS、relay、Rill 存在或缺失、IPv6/多用户/自定义配置。
3. **拒绝路径**：无 TTY、自动更新、`--yes`/`--allow-major`、用户拒绝、旧 XTLS、损坏/混装 config，一律不下载/激活 Go。
4. **中断恢复**：在 `PREPARED`、`ACTIVATING`、入口切换后、cron 切换后、提交前后注入强杀和重启；独立恢复器可恢复到正确管理器状态或明确保留恢复材料。
5. **Go 已提交后**：确认旧 Bash 备份不能被 cron 再启动、旧目录不参与正常控制；如考虑回 Bash，应另设有权限/确认的恢复流程，不做静默反迁移。

## 5. 发布物与工作流

- Go `linux-amd64`、`linux-arm64` 两类正式产物，明确架构和构建 Go 版本；生成 SHA256SUMS/manifest，锁定依赖/源码提交。
- 新用户 Go 安装器可按架构下载固定资产，校验后受控安装；与旧 Bash 的 `v3.x` 固定发行/资产命名互不混淆。
- 先在候选 Release 与隔离测试 VPS 上验证，再把 `develop/go-native` 合到 `main`；保留 `legacy/bash` 维护旧安全更新。**仅分支存在并不足以保证旧更新器继续工作**，仍需 API `shell_online_version` 及固定 Bash candidate 正确。
- 发布文档明确变更：取消默认 SELinux/limits 系统级调优；部分不安全 TCP/测速工具可能延期；只读接口不再隐式修复；旧 XTLS 无法直接迁 Go。
- 记录恢复命令和恢复材料位置、敏感信息处理、不收集无必要遥测。无需构建插件市场和 Web。

## 8. 发布后最小维护原则

仅保留必要的安全修补、兼容回归与更新来源验证；不以“Go 已发布”为理由立即扩张 sing-box、多节点或 Web。先把旧 Bash 用户迁移和 Go Xray 日常变更稳定一段受监测的维护周期，再单独规划第二内核。
