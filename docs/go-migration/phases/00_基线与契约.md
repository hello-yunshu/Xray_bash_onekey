# Phase 00｜深度基线冻结、资源所有权和双通道迁移契约

**阶段性质：** 审计与契约冻结。**不得修改生产路径、不得切换 Bash 主线、不得开始大规模 Go 业务编码。** 可为校准契约添加只读检查器、样本和回归用例。

## 0. 输入与既有决策

- 先读取本包 `README.md`、`reference/AUDIT_REPORT.md`、`reference/TRACEABILITY_MATRIX.md`、`reference/RELEASE_MIGRATION_CONTRACT.md`、`reference/MIGRATION_TRIAL_REPORT.md`。
- 工作基线：`hello-yunshu/Xray_bash_onekey@4752f77c58028ac169c429fe7674c20060b30c9e`、Bash v3.3.4；开始执行当天**重新核对远端 commit**，若主线变化，先做差异审计，不直接把旧结论套用到新代码。
- 当前 `main` 为稳定 Bash；Go 只在 `develop/go-native`。在用户没有批准真实迁移前，禁止远端 PR 修改旧用户升级方向。
- 本阶段仅 Xray 与独立 relay；不做 sing-box 正式功能、Web、动态插件、通用 Linux 平台、多 VPS 运维。
- 已确认的安全原则：停止默认 SELinux/limits 全局调优；仅操作受管理文件/cron/jail/防火墙；纯查询零系统写入且无外部更新请求（Stats 允许本机 Xray API）；手动 TTY 才能授权 Go 迁移。

## 1. 交付目标与完成定义

产生可直接被 Phase 01–04 代码依赖的**权威契约**，而非仅一份长篇讨论文档：

1. 完整的 Bash CLI / 数字菜单 / Docker / Rill / 自定义配置**功能覆盖矩阵**，每行都能追到 Go 代码责任和验证方式。
2. 现有系统资源（文件、服务、二进制、账户权限、cron、规则）**所有权台账**，明确旧归属/第三方归属/未知归属。
3. Go 新管理元数据 JSON Schema 草案和旧字段映射，明确原 Xray JSON 为运行事实源。
4. Bash/Go 双 Release、双 metadata 与迁移授权/回滚契约。
5. 一套独立于线上数据、可复现的代表样本集与高风险失败用例。
6. 当前 CI 红灯、跨仓库版本不一致和缺失记录按 `已证实 / 待复现 / 不支持` 分类。

### 00-C｜系统资源所有权核对

必须按下表逐项建立真实台账并给出清理规则：

| 资源类别 | 必查对象 | 需要回答的问题 |
|---|---|---|
| 配置 | `/etc/idleleo/conf/{install_config.json,xray,nginx}` | 是否仅改管理器自己创建的片段？自定义 DNS/outbounds/routing 怎么保留？ |
| 二进制 | `/usr/local/bin/xray`、`/usr/local/nginx`、未来 `/opt/idleleo/bin/idleleo` | 哈希、备份、用户/组、是否含非项目内容？ |
| Unit | `/etc/systemd/system/{xray,nginx}.service` | 哪个组件创建？初始 active/enabled 如何恢复？ |
| 证书 | `/etc/idleleo/cert`、`/root/.acme.sh` | 私钥权限、证书续期任务、第三方 ACME 账户归属？ |
| 定时任务 | root crontab 的 auto_update/ssl_update/geo_update | 项目任务是否精确识别？不得删其他行 |
| 防火墙 | iptables/ip6tables 与保存脚本 | managed port 对象/用户手动规则如何区别？ |
| Fail2ban | `/etc/fail2ban/jail.d/`、`jail.local` | 禁止 `*.local` 全删；不自动卸载别人安装的服务 |
| Rill | `/etc/rill-xray-agent`、独立权限/服务 | Agent 生命周期独立，Go 更新不破坏授权状态 |
| Docker | fake-systemctl、entrypoint、volume | 容器不能直接复刻宿主 systemd DBus 操作 |
| 全局系统 | limits、SELinux、sysctl | Go 不自动扩大改动；不自动回退已存在的旧值 |

输出 `docs/go/RESOURCE_OWNERSHIP.md`，对每条路径声明 `owned / shared / user / unknown`，以及允许操作（读/改/删/迁移）和失败恢复手段。

### 00-D｜字段级 Bridge 转换契约

- 逐一解析 `install_config_reality()`、TLS/None 配置写入函数和 relay 配置保存函数，列旧数据字段类型与允许缺省值；对历史版本的不同 key 命名建立最小分支表。
- **优先保留运行 Xray/Nginx 原生配置不动**；Go manager.json 不得把私钥、UUID 与客户短 ID 复制到第二份状态 JSON；如必须保存，需要单独列出原因和权限/备份策略。
- 旧 `privateKey`/`publicKey`/`password`、`id`/`multi_user`/`reality_clients`、`shortIds`/`spiderx_path`、`network_mode`/IPv6、`shell_mode`/role/relay 字段均须有一致性检查。
- 复核旧 `info/*.inf`、原生 Xray `routing/dns/outbounds`、自定义 Nginx include。无法安全解析的内容保留原样或阻断迁移，绝不静默重建。
- 结合 `probe/` 已验证的流程，写 `docs/go/CONFIG_BRIDGE_CONTRACT.md`：识别、Plan、Prepare、Validate、Activate、Recover 的输入输出和失败模式；原型不可直接合并生产。
- 确认真实 Xray service 运行路径与配置实际位置，不因为目标 Go 目录看起来更漂亮而搬迁。

### 00-E｜发布与迁移协议冻结

- 不让旧 Bash 自动更新字段指向 Go；设计桥接版 Bash *先发行* 的时间顺序及与旧 `v3.x` 发行物的兼容。
- 冻结 Go 独立 release 标签/asset、候选源码 SHA/摘要来源、Go 更新流程、`releases/latest` 行为、资产校验、API metadata 的字段名。
- 双层用户确认：旧 Bash 真正 TTY 手动检查更新，阅读迁移影响并明确同意，**之后才首次下载 Go Bridge**；自动更新和参数 `--yes`/`--allow-major` 不能代替迁移同意。
- 冻结 `PREPARED→VALIDATED→ACTIVATING→COMMITTED` 的 Journal 和独立恢复器；定义三类回滚：激活前、激活过程中、提交后明确另行授权。
- 明确锁与任务切换：旧 cron、Go 任务、证书续期、Xray/Nginx 更新不得同时修改同一资产。
- 输出 `docs/go/RELEASE_MIGRATION.md`，至少覆盖本包 `reference/RELEASE_MIGRATION_CONTRACT.md` 的全套禁止场景。

### 00-F｜准备代表样本和测试签名

- 至少真实生成五类**非生产数据样本**：Reality 直连、Reality+Nginx、TLS 多传输、独立 relay、带用户自定义 DNS/outbounds/routing + 多用户的场景；还要有 XTLS 旧模式拒绝样本。样本只能用合成密钥，不能提交真实 VPS 私钥。
- 用当前 Bash 的生成器/仓库模板作为样本的事实来源；所有样本标明来源 SHA、生成命令、关键字段与脱敏方式。
- 若 Go 原型和生产 Schema 定义冲突，先修改 Schema，再逐用例核验；不能为了让原型继续绿灯就扭曲旧数据事实。
- 把 R01–R24 全部映射到最少一条测试或显式人工验证，按风险优先，避免无意义复制八十多套 Shell 测试。
