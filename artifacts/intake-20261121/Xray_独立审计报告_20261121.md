## 3. 独立执行与源码审计

### P0-01 cert clear 引用识别不完整

`internal/deploy/certclear.go:43,91–154,397–462`。正则仅匹配行首指令；真实 Nginx 允许 server 块中同一行放置多个指令。本轮用提取原正则运行，合法行内两个证书指令输出 0 条，nginx -t=0；移动测试证书后 nginx -t=1；恢复且按多行格式编排，nginx -t=0，识别 2 条。证据 `nginx-probe.log`。

源代码将 refs 提交 planManagedDir，再 executeCertClear；未见清理后 nginx -t 在 ClearCertificates 主流程中执行。collectCertReferences 对指定目录外 include、relative path、读取错误及某些 symlink alias 的处理也需核验。`classifyManagedFile` 对管理标识、约定文件名与点文件的归属判定另需加第三方 canary。风险：被误判为无引用的项目证书可能被删除、服务下一次 reload 失败。已证实检测缺陷以及 Nginx 缺证书的后果，未证实完整 CLI 删除链路。P0 指阻断整改优先级，并非声称已复现生产事故。

修复：优先安全拒绝、真实生效配置和 include 链扫描、不可判定引用保留、相对路径按真实前缀解析、校验配置后才提交删除事务，回滚保留失败证据；不要引入泛化大框架。

## 5. 最终建议

优先解决 P0 并补关键双端，之后再收敛覆盖，不新增框架或 Web、不追求形式上的 Bash 复制。安全增强允许有意识差异，但必须证明 Go 行为正确且 Bash 风险不传播。Go 是唯一管理核心，受控 Shell 辅助，不扩大范围到平台化。将最新提示词交给 Trae 用本地 Docker 进行独立/双端验收。只有一致 SHA 的真实证据、全部适用必需项通过且未执行边界明确时，才讨论候选 GO；正式发布另需授权与 VPS 边界验证。
