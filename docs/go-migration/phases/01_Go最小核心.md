# Phase 01｜Go 单二进制管理核心、纯查询与安全变更原语

**阶段性质：** Go 基础实现，但**绝不替换正在运行的 Bash 正式入口**。依赖 Phase 00 契约完成；候选程序只能在测试路径/隔离环境运行。

## 0. 目标与非目标

产出一个可在目标 Linux 服务器离线启动、能读旧/新配置、并可安全对一项**隔离测试资源**进行候选修改/验证/恢复的 Go 管理器。不是重写全部 Xray，也不是实现插件平台。

- 轻量：Go 单二进制、无管理 daemon、无 Web API、无数据库，普通读操作不访问外部更新服务器、不做文件写入（`--stats` 允许访问 `127.0.0.1` 本机 Xray Stats API）。
- 安全：明确定义 `READ_ONLY`、`LOCAL_MUTATION`、`NETWORK_MUTATION`；所有 root 执行须经单一路径，不拼接 shell 命令。
- 稳定：不把“原子 rename 一份 JSON”等同于“整个 VPS 事务”；跨配置/服务行为使用紧凑日志和可验证恢复。
- 兼容：保留旧 Linux/systemd、amd64/arm64、非 TTY、窄终端、多语言、机器 JSON 和旧参数语义的入口空间。

## 1. 建议包结构（可根据 Phase 00 微调）

```text
cmd/idleleo/main.go
internal/cli/              # cobra/数字菜单/旧别名/输出和退出码
internal/app/              # 统一 use case，单一操作授权点
internal/store/            # manager schema、运行配置只读视图
internal/host/             # 文件、锁、systemd CLI/接口、账号、下载
internal/change/           # 候选、校验、事务记录、commit/recover
internal/runtime/          # 原生 Xray/Nginx 运行路径与能力的抽象
internal/compat/           # 历史 flag 的薄适配与行为断言
```

不提前创建动态 `.so` 插件、gRPC 服务、通用 Linux 软件市场。`legacybridge` 正式业务到 Phase 03 才需要，但这里定义可复用的日志/路径与校验接口。

## 2. 分批实施（每批应可独立构建）

### 01-A｜CLI 与纯查询

1. 最小 `idleleo --help`、`version`、`status`、`show`、`config inspect`；交互数字菜单仅作为**显式无参数 TTY**入口。无 TTY 无参数时清晰错误（或打印帮助）并以规定退出码返回，不等待无限输入。
2. `--help` 在未安装、无 root、无网络、没有任何配置时都可用。`status/show` 不修改配置、日志目录、软链、权限或 cron。
3. 兼容 `NO_COLOR`、`TERM=dumb`、重定向、40/60/80 列、中文字符宽度、Ctrl-C/EOF、简短错误输出。六语言使用内置/随程序资源回退，不为了加载语言包调用 apt/dnf。
4. `--stats --json` 与历史退出码先定义 schema/命令派发，占位接口不得假返回统计 0；未实现的子命令返回显式 `not implemented` 的非零码，不能误报成功或跳回菜单。
5. 所有 read-only 命令由同一个无写入上层接口驱动，禁止调用 `ensure*`、`repair*`、`download*` 函数。把检查/修复拆成不同显式命令。

### 01-B｜规范状态与文件权限

1. 管理器配置保存 `schemaVersion`、`activeEngine=xray`、节点角色、受控字段/资源、真实运行配置路径、上次成功配置摘要；**不重复存储 Reality privateKey、UUID、shortId**，仅引用实际文件/受控资产。
2. JSON 错误必须区分缺失、损坏、Schema 版本过高、未支持旧模式、与实际运行配置矛盾；错误不引起 Xray/Nginx 自动停启。
3. 遇到原生 Xray 配置自定义字段，先创建只读结构化视图；后续更改使用基于当前字节/JSON 节点的受控最小修改，不能从 manager.json 重建整份原文件。
4. 状态文件权限受限（例：manager `0600` root:root），必要时用 systemd 服务用户权限读取实际 Xray JSON。必须根据 Phase 00 的服务账户事实来确定权限，不能一律改成 root 拥有。
5. 读写路径必须对符号链接、上级目录越界、失效软链、未知原始权限保持谨慎。不得试图自动“清理”旧配置树。

### 01-C｜受控执行、锁与安全文件变更

1. 所有外部命令只用 `exec.CommandContext(binary, args...)`、固定 PATH、超时/取消、退出码、输出限制与脱敏。不执行 `bash -c` 拼接用户输入；受控 Shell/Python 组件必须单列在契约清单。
2. 实现排它更新锁、进程退出自动释放、同操作并发冲突报告；不要对纯读取使用重写锁。更新锁应与既有 `/run/lock/idleleo-update.lock` 的迁移切换窗口兼容。
3. 关键文件写入标准：读取实际旧内容和身份→计划最小 diff→在同一文件系统暂存→保留权限/owner→用指定校验器验证→原子替换单文件→服务实际检查→写有界事务记录。**多文件与 systemd 不能假设全局原子。**
4. 回滚时遵守原有 active/enabled；已停的服务不被意外启动。恢复失败应留下 `RECOVERY_REQUIRED`、原文件、变更差异和操作步骤，终止进一步自动清理。
5. 遇到用户手动修改导致 SHA/指定 JSON 字段偏移：重新读取并判断安全局部合并，否则拒绝，而不是覆盖。
6. 用一项非生产的样本配置/假服务完成完整变更演示；将“配置校验失败、写失败、服务失败、重启后残留 Journal、外部同时修改”每种至少注入一次。

### 01-D｜内核适配最薄边界

只定义：`Runtime.Inspect()`、`Config.Validate(candidate)`、`Runtime.Status()`、`Runtime.Apply(change)`、`Runtime.Restore(snapshot)` 这类**最小职责**。不得强行将 Xray、Nginx、未来 sing-box 所有属性放入一个超大 Schema。Phase 02 再填实现，首版不得直接引入动态插件框架。

## 3. Go 原型与正式代码的区别

本包 `probe/` 已验证有限的 `Inspect/Prepare/Activate/Recover`，但它是故意要求沙盒标记的**证明用原型**：

- 不应把原型 JSON 当生产 Schema 固定发布；先以 Phase 00 的字段映射为准。
- 原型中把旧入口字节放 Journal 只为快速模拟，正式版使用受限快照与摘要，不让日志变成秘密副本。
- 原型没调用 Xray/Nginx；Phase 01 必须连接真实目标校验器的安全执行接口（必要时用 mock + 一个真实二进制冒烟）。

## 4. 建议阶段内提交

- `P01-1`：Go 模块、CLI/数字菜单、离线/无副作用命令与错误码骨架。
- `P01-2`：状态/权限/路径/配置读取、锁与统一执行器。
- `P01-3`：安全文件变更与故障注入；补充本阶段契约和测试证明。

每批提交前构建、go test、Go vet、必要时 race 与最小 Docker/VM 检验，不要求首次就有完整端到端系统。

## 5. 最低验收用例

| ID | 步骤 | 必须证明 |
|---|---|---|
| C01 | 断网运行 `--help/version/status` | 零外部 curl/apt/dnf、零 `/etc` 写入、零服务重启；`--stats` 允许本地 Xray API |
| C02 | 无 TTY/EOF/TERM=dumb | 不挂死，不输出错误颜色字符，退出可解释 |
| C03 | 未安装/损坏 manager.json | 能报告错误，不下载、不重建、不重启 |
| C04 | 有自定义 routing/DNS/outbounds 的 Xray 配置 | `status` 读取不改变 SHA；不识别项不能被覆盖 |
| C05 | 用户配置外部漂移 | 写之前发现冲突；未批准时保持旧文件 |
| C06 | 校验器返回非零 | 不触碰实际文件/服务 |
| C07 | 文件写失败/权限失败 | 恢复或保留完整恢复材料 |
| C08 | 模拟服务启动失败 | 事务不标记成功，尊重原 active/enabled |
| C09 | 两个修改并发启动 | 同一资源只能有一组变更进入执行 |
| C10 | 非 root 查询与非法命令 | 权限准确、非法参数非零，不回菜单 |
| C11 | Linux amd64 + arm64 编译 | 构建成功，arm64 真机执行可延至 Phase 04 |
| C12 | 管理入口只存在候选路径 | 旧 Bash 主路径未变化，旧 cron 仍正常 |

## 6. 阶段退出门禁

- [ ] 单 Go 管理二进制可编译；普通管理和纯读**不调用 Bash `install.sh`**。
- [ ] 纯查询断网/无 root/无配置/无 TTY 条件符合契约。
- [ ] 目标运行文件原样保留，至少可解析真实 Bash 样本和一个自定义配置样本。
- [ ] 安全变更“正常/校验失败/写失败/服务失败/外部漂移”有实际日志和测试证明。
- [ ] 服务恢复不会把原先停止的 Nginx/Xray 意外启动。
- [ ] 未增加 Web、daemon、强制数据库、全局 SELinux/limits 写入。
- [ ] 仍使用旧 Bash 正式入口，Go 候选仅在隔离测试目录可执行。

## 7. 开发智能体指令

> 只执行 Phase 01。先核对 Phase 00 的资源、Schema、CLI 和测试契约，在 `develop/go-native` 分批实现 Go CLI/离线状态、只读配置视图、统一文件/服务执行器及一项可故障注入的受控变更。不要实现完整 Xray 安装、发布 Bridge 或改动旧 Bash 正式入口；保持单机、零 daemon。逐条提交 C01–C12 的命令/日志证据，任何未验证项目保留未完成状态。

- `go test ./...`、`go test -race ./...`、`go vet ./...` 和 L0 的版本比较、IP/中转地址、xHTTP 路径、IPv6 URI、URL 编码通过。
